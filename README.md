# qorganwork / qwork

Мобильное приложение для выездных работ: задачи, рабочее время, поездки, фотоотчёты и согласования. Один интерфейс qwork используется на iOS, Android и в браузере телефона.

**Открыть приложение:** https://vector-iepg.vercel.app

На сайте включён демо-режим без регистрации: выберите «Сотрудник», «Руководитель» или «Бухгалтер». Роли можно переключать внутри приложения. Демонстрационные заявки и командировки сохраняются в этом браузере; реальные данные компании не открываются без авторизации.

## Структура

- [mobile](mobile/README.md) — React Native / Expo, включая браузерные адаптеры.
- [backend](backend/README.md) — API на Java 21 / Spring Boot с SQLite или PostgreSQL.
- [QWORK-PILOT.md](QWORK-PILOT.md) — подготовка пилотного запуска.

Старый HTML-макет «Вектор» удалён из текущей версии. При необходимости его можно найти в истории Git.

## Разработка

Нужен Node.js 22.13 или новее. В папке `mobile` выполните `npm ci`, затем `npm run web` для браузера или `npm start` для iOS/Android. Адрес API задаётся через `EXPO_PUBLIC_QWORK_API_URL` в локальном файле настроек; подробности — в README приложения.

## Публикация на Vercel

Проект Vercel: `vector-iepg`, корневая папка репозитория. Конфигурация `vercel.json` устанавливает зависимости в `mobile`, собирает Expo Web с `EXPO_PUBLIC_QWORK_DEMO_ONLY=1` и публикует `mobile/dist`. Серверные запросы `/api/*` перенаправляются к существующему API `https://qwork-api-v5f3.onrender.com`; проверка авторизации API сохранена. Для сборки с обычным входом уберите флаг демо-режима и пересоберите приложение.

Сервер Java разворачивается отдельно. Локальные настройки, пароли, базы данных, зависимости и нативные сборки не загружаются на Vercel.

Веб-версия сохраняет мобильный дизайн. В демо-режиме после обновления страницы достаточно снова выбрать роль. Быстрый вход по PIN, биометрия и фоновые push-уведомления остаются функциями установленного приложения. Камера и геопозиция в браузере требуют HTTPS и разрешений. В сборке с обычной авторизацией после обновления страницы нужно войти повторно; исходные мобильные сборки продолжают поддерживаться.

npm run test:accounting

EXPO_NO_DOTENV=1 EXPO_PUBLIC_QWORK_API_URL=/api npm run build:web

Тесты проверяют сохранение очереди фото при перезапуске, повторную отправку после потери сети, изоляцию аккаунтов, откат при ошибке сохранения, ссылки приглашений и действия при приёмке отчётов.

## Демо кабинета бухгалтера

В роли «Бухгалтер» доступны проверка заявок, авансы, сверка фактических расходов и договоры. Кнопка «Добавить учебные примеры» создаёт явно помеченные вымышленные данные один раз; собственные командировки сохраняются.

Новые заявки проходят проверку расходов бухгалтером, затем согласование руководителем. Бухгалтер может вернуть заявку с замечанием, сотрудник исправляет её и отправляет повторно. Существующие заявки с прежним маршрутом согласования продолжают работать.

После согласования можно записать аванс, после завершения поездки — сверить расходы с фотографиями чеков или оригиналами документов. Остаток считается как фактические расходы минус авансы и доплаты плюс возвраты. Оплата работы по дневной ставке учитывается отдельно. Изменённый отчёт или новые чеки требуют повторной сверки. Сотрудник видит аванс и замечания в своей поездке.

Это локальная демонстрация: данные общие только для ролей в одном браузере и не синхронизируются между телефонами. Финансовые действия лишь сохраняют отметки, не переводят деньги и не создают документы в 1С/ИС ЭСФ. Кабинет с обычной авторизацией и серверные права доступа не изменены.

На сайте командировки, финансовые отметки, документы и чеки сохраняются атомарно в IndexedDB (`qwork-demo-v1`). Существующее демо из localStorage переносится при первом успешном сохранении; исходная запись остаётся нетронутой как резервная копия. Ошибка записи не сбрасывает данные, а одновременное изменение в другой вкладке требует обновить карточку. На телефоне в нативном приложении сохраняется прежнее хранилище.

К поездке можно прикрепить до пяти фото чеков. Снимок автоматически уменьшается без обрезки до 2400 пикселей по длинной стороне и сохраняется в JPEG примерно до 1,5 МБ. После загрузки можно открыть фото и проверить текст. При ошибке кнопка повторного сохранения использует тот же идентификатор, чтобы не добавлять дубликат. Данные по-прежнему привязаны к браузеру: очищать данные сайта для исправления ошибки загрузки не нужно.


## Заявления и документы на подпись в демо

В роли сотрудника и бухгалтера появился раздел «Документы». Профиль сотрудника по-прежнему доступен через кнопку вверху; договоры бухгалтера — через плитку на главной странице.

- Сотрудник создаёт заявление на аванс из согласованной незавершённой поездки. Сотрудник, место, цель и даты заполняются автоматически. Черновик с положительной суммой можно сохранить даже при исчерпанном остатке; форма показывает план, уже выданный аванс и доступную сумму. Подписание, отправка и принятие заявления проверяют актуальный остаток плановых расходов без оплаты работы. Сохранение черновика не означает разрешение на выдачу денег. После просмотра сотрудник явно подтверждает учебную подпись и отправляет заявление бухгалтеру.
- Бухгалтер принимает заявление либо возвращает его с замечанием. По принятому заявлению можно отдельно записать частичную или полную выдачу. Подписание и принятие заявления не создают финансовых операций.
- Бухгалтер формирует учебный авансовый отчёт из завершённой поездки с фактическими расходами или акт списания с описанием материалов. После отправки сотрудник читает документ, подписывает в демо или возвращает с замечанием; затем бухгалтер ставит свою учебную подпись.
- Исправления сохраняют новую версию. Содержание и учебные подписи прежних версий остаются в истории. Изменение расходов или чеков останавливает подписание устаревшего авансового отчёта до его обновления. Подписанный документ сохраняет исходное содержание.
- «Добавить примеры документов» один раз добавляет учебный отчёт и акт на подпись, а при необходимости — существующий набор учебных поездок. Данные пользователя не очищаются.

Проверка: сотрудник → «Документы» → «Добавить примеры документов» → открыть документ → «Подписать в демо» → переключиться на бухгалтера → «Документы» → подписать тот же документ. Отдельно можно пройти заявление → принятие бухгалтером → частичная выдача → остаток у сотрудника.

Это локальные учебные отметки, не ЭЦП и не юридически значимый документооборот. Ключи не запрашиваются; 1С и загрузка официальных документов пока не подключены. Между разными телефонами данные не синхронизируются. Сверка расходов и реальные документы остаются отдельными от демонстрации подписания.

## Автоматическое посещение объектов в демо

В карточке поездки руководитель один раз указывает здание на карте (либо точные координаты) и радиус 50–300 м. Точка сохраняется для следующих поездок с тем же названием и городом. Центр города и название организации не считаются координатами здания. Сотрудник не может менять расположение объекта.

Сотрудник открывает активную поездку и включает автоотметку, разрешив GPS. Кнопка «Посетил» в демо удалена. В согласованные даты поездки посещение ставится автоматически после 60 секунд у единственного подходящего объекта: нужны свежие последовательные измерения с погрешностью не более 50 м, без перерыва более 30 секунд. Погрешность целиком должна помещаться внутри заданного радиуса. При наложении зон двух объектов отметка не ставится. Известные подставные координаты Android отклоняются. Это проверка присутствия устройства, а не доказательство выполненных работ или защита от намеренной подмены геолокации.

Проверка работает только при открытой карточке и активном экране. При сворачивании, потере связи, выходе из зоны или неточном GPS отсчёт начинается заново. Координаты не отправляются стороннему сервису: вместе с отметкой в локальном демо сохраняются последний замер, точность, расстояние, длительность и использованная точка объекта; непрерывный маршрут перемещений не сохраняется. Фоновые геозоны с заблокированным экраном требуют отдельной реализации и разрешений в нативном приложении. Справка по ограничениям: [W3C Geolocation](https://www.w3.org/TR/geolocation/), [Expo Location](https://docs.expo.dev/versions/latest/sdk/location/).

Прежние ручные отметки остаются с пометкой «Отмечена вручную ранее» без выдуманного GPS-подтверждения. В активной поездке сотрудник может отменить ошибочную отметку с обязательной причиной; исходное время и подтверждение остаются в истории. Повторная отправка события не дублирует и не восстанавливает отменённую отметку. Рабочий сервер с обычной авторизацией этим демонстрационным изменением не затрагивается.
